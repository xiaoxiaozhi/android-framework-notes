# Android Framework 源码带学

对话式带学 Android framework 子系统，必要时把本篇落盘成 HTML。先读 `references/writing-style.md` 拿到写作质量标准与反面清单；要落盘时再读 `references/html-production.md`。

## 触发分层

- **「学习 XXX」= 定主题**（学习 WMS、带我读 Input、啃 SurfaceFlinger…）：建立 3-7 站路线，本会话沿用，决定代码取舍方向。
- **「分析 YYY」= 具体任务**（分析 relayoutWindow、ANR 怎么触发…）：在当前主题下裁剪讲解。合体「学习 XXX，分析 YYY」直接开讲。
- 主题有粘性：之后直接甩方法名、「继续」「下一站」都挂当前主题；新「学习 ZZZ」才切题。
- 无主题直接「分析 YYY」：一句话推断默认主题（例：「默认按 WMS 讲」），不长篇反问。
- 触发后不复述、不客套，直接进入。兜底可用 `/skill android-framework-tutor <内容>`。

**边界**：审查/review/找 bug → code-review；通用源码转 HTML（非带学）→ android-source-html-analyzer；多篇系列的审计/补篇/重排 → android-article-series。本技能只做「带学 + 本篇直接落盘」，落盘后不把质量返工甩给别的技能。

> 通用约束：不写死机器、绝对路径或 AOSP 版本；源码根、目标目录、版本号运行时解析。

## 步骤

### Step 1　定篇幅与叙事轴
- **简单**（小方法/标志位/一行配置/概念）：3-8 句白话 + 必要时 3-5 行代码；不出四要素、思考题、下一步，不主动问落盘。
- **中等**（一个方法/短链路）：锚点 + 开篇 + 1-3 个代码块。
- **复杂**（跨进程/状态机/整站）：完整流程。
- 叙事轴二选一并贯穿全篇：**数据流**（buffer/transaction/事件对象逐跳被加工）或**事件流**（回调/状态变化驱动）。块序 = 流序：起点 → 每跳形态怎么变 → 终点。分叉/回环要显式画出来，不许隐去。
- 判据：删掉任何不服务于本问题的「设计意图/思考题」段落，若答案仍完整就删。模板是上限不是下限。

### Step 2　开篇定位（第一块代码前）
一段连贯文字（短 3-5 句、长 1-2 段），自然覆盖四问，**不要四个小标题、不要「这是什么：」标签**：①一句话定位属于哪层、解决什么；②真实场景（开发/ROM 定制/排障会碰到什么现象）；③1-2 个设计取舍 + 「反过来设计会怎样」；④3-6 个已核实的真实参与者（类/线程/进程）与「起点→终点」主流程。简单问题压成 1-3 句，但「是什么 + 用在哪」不能省。

### Step 3　现地核实源码（强制，先查后讲）
- 源码根解析顺序：用户给定 → 配置 `skills.entries.android-framework-tutor.config.aospRoot` / 环境变量 `AOSP_ROOT` → 本会话已确认的根 → 都没有就问一句，不猜。
- 任何讲解前以当前源码树为准：`ls` 确认文件 → `grep -n` 定位方法 → 取真实片段 → 以片段为底本。旧路线图/旧文章的行号锁位置只当线索，必须重新 grep。禁止跨 `/mnt`、`/home` 全盘 find。
- 源码在 WSL 用 `wsl -e bash`，复杂逻辑写临时 `.sh`（见 wsl-script-exec 技能）；本机路径直接用。
- 用户直接贴代码则以贴的为准，不臆造行号。
- **判据：每个代码块标题带 `文件:起始行`，且行号是本次现查的；参与者类名/线程名真实存在。**

### Step 4　裁剪大方法 + 跟块讲解
- 大方法（performSurfacePlacement、relayoutWindow 等）**绝不整段贴**：每行必须服务于当前主题或本次问题，无关分支用一行占位 `// … 省略：xxx 分支（何时走、为何与本任务无关）`。
- 关键行旁加中文注释，**写 why 不写 what**（锁为何在这、为何 post Handler、状态为何这个顺序）。单块 ≤40 行，超长拆 A/B 并标阅读顺序。
- **每个代码块正下方立刻跟讲解**，不许先列完代码再统一讲。按块取舍四要素：这段在干什么（交代进入/出去的数据形态）、设计意图、实战问题（现象→因果→怎么查：dumpsys/event log/断点）、主线位置（`上游#方法 → 本方法 → 下游#方法`）。
- 标题写成 `块B｜第2跳：xxx`；分叉用 `块B1/B2`，汇合块说明汇合点。
- 跨块才能讲清的实战问题/思考题，只放在闭环的最后一块，并标「（需结合：块X、块Y）」。
- **判据：只看注释就能复述主路径，并说得出每个省略分支何时执行。**

### Step 5　思考题
跟着块走：单块题放该块末尾，闭环题放闭环块下并标注需结合哪几块；全篇 2-4 题、由易到难、优先实战排障型。用 `🧠 思考` 引出。只出题不给答案，用户答了再点评，说「跳过」就不追。纯 getter/胶水代码不出题。

### Step 6　交互节奏
一次讲一个方法/一站；复杂主题结尾给「下一步」①主线下一站 ②深挖某下游（真实方法名）。简单问题答完即止。用户回方法名/「继续」/「①」即续，无需再喊触发词。当前主题已有同系列 HTML 才提示配套阅读。

### Step 7　落盘成 HTML（说「落盘」即直接写正式文件）
完整流程、样式硬要求、模板、验收脚本都在 **`references/html-production.md`**，落盘前必读并用其中脚本验收。要点：
- 默认只在对话讲；复杂/中等主题末尾问一句「是否落盘成 HTML？」，简单问题不问。
- **没有 `_draft`**：说「落盘/出稿/生成 HTML」= 直接在目标目录写正式 HTML，当场续编号、更新 `index.html` 与相邻篇上下篇链接，写完打开浏览器。
- 样式直接套 `assets/template.html`，不再每篇逆向旧 CSS；锚点必须过 `scripts/audit_anchors.py`，结构过 `scripts/check_html.py`，并 Edge 截图。

## 对话输出骨架

```text
> 📍 主线第 N 站：站名
> 上游：X#foo() → 本方法：Y#bar()（文件:行号）→ 下游：Z#baz()
> 🧭 数据流/事件流｜起点：… → 终点：…

开篇定位（一段话，不分小标题）

### 块A｜第1跳：标题（文件 a-b 行）
​```java
// ① why 注释
// … 省略：xxx 分支（触发场景；为何无关）
​```
（讲解紧跟其下）
🧠 思考：【单块】…

### 块N｜第N跳（闭环块）
**实战问题（闭环）**：（需结合：块A、块C）…
🧠 思考：【闭环·需结合块A、块B】…

**下一步**：① … ② ……
**是否落盘成 HTML？** 回复「落盘」直接写入 <目标目录>（自动续编号、更新 index 与上下篇）。
```

简单问题不套骨架：一句话结论 → 必要时 3-5 行关键代码 → 一句注意点，答完即止。
