# 写作质量标准（带学讲解 & HTML 文章通用）

SKILL.md 管流程，本文件管**内容质量**。每次开讲或落盘前对照本文件；交付前过末尾的评分卡，不达标就重写，不要硬交。

## 一、信息原则

1. **先立「为什么」，再讲「是什么」**：先给机制存在的理由和它解决的矛盾，再堆事实。读者记不住 API，但记得住取舍。
2. **具体压倒抽象**：任何结论必须能落到「真实类名/线程名 + 方法名 + 文件行号」。禁止「系统会处理」「框架在这里做了优化」这类无主语句子。所有锚点现地 grep 核实（SKILL.md Step 3），旧文章行号一律重查。
3. **代码块是主角，文字围着代码走**：每块代码正下方立刻讲解；讲这段进入时数据/状态是什么、出去变成什么。接不上流，就是块切错了。
4. **裁剪而非搬运**：大方法只留服务于本问题的行，省略分支必须用一行占位写明「何时执行、为何与本任务无关」。贴整段源码 = 失败。
5. **注释写 why**：解释锁为什么在这、为什么切线程、状态为什么是这个顺序；不写 `i++; // i 加一` 这种废话。

## 二、叙事原则

- 全篇只有一条主轴：**数据流或事件流**。块 A/B/C = 流经的第 1/2/3 跳，标题直接写 `块B｜第2跳：xxx`。
- 分叉画分叉（块B1/B2），回环画回环（多次 relayout、合成回路），并说明回到哪一步。隐去环 = 失败。
- 调用链一律用属性风格树，不用箭头长句：

```text
ViewRootImpl#relayoutWindow()              [ViewRootImpl.java:1024]
├─ WindowSession#relayout()  // 跨进程进 system_server
│  └─ WindowManagerService#relayoutWindow() [WindowManagerService.java:??? 已核实]
└─ SurfaceControl.Transaction#apply()       // 出锁后提交，避免持锁等 SF
```

## 三、排障内容必须可操作

实战问题按「**现象 → 与这段代码的因果 → 怎么查**」写，第三段必须给可直接执行的抓手：具体 `dumpsys` 子命令、event log/trace 关键词、或该方法内的断点位置。只堆 ANR/黑屏/掉帧名词而不给查法 = 凑字数，删掉。

## 四、反面清单（出现任意一条，重写）

- ❌ 凭印象写类名/行号/锁；锚点没在当前源码树 grep 过。
- ❌ 开篇做成「这是什么：/设计思想：/机制骨架：」四个小标题或四条 bullet（应是一段话）。
- ❌ 整段贴几百行大方法让读者自己找重点。
- ❌ 先列完所有代码块再统一讲解。
- ❌ 「A → B → C → D → E」一长串箭头当调用链。
- ❌ dumpsys/trace 命令没验证过参数是否存在。
- ❌ 为套模板给纯 getter 加思考题、给简单问题硬凑名词表/方法表/闭环。
- ❌ 分片并行写正文再拼接（part1…part6）：**脚本可以分块构建，叙述必须一气呵成**，否则气脉断裂。
- ❌ 用「本文将介绍…」「综上所述…」这类水文开头结尾。
- ❌ 把前一篇文章当必读前置（每篇独立成篇，前篇只能是延伸阅读）。

## 五、好/坏片段对照

**坏**（抽象、无锚点、注释是废话）：

```java
int relayoutWindow(...) {
    ...
    mWindowSession.relayout(...);   // 调用 relayout
    ...
}
```
> relayout 是窗口更新的重要方法，系统会在这里处理 Surface，然后进行后续流程。

**好**（裁剪、why 注释、有流、有锚点）：

```java
// ViewRootImpl.java:1024（行号已在 android-12.0.0_r32 现查）
int relayoutWindow(...) {
    // … 省略：mAttachInfo 更新分支（仅首帧走，与本次「Surface 何时更换」无关）
    int res = mWindowSession.relayout(... , mPendingContentInsets,
            mSurfaceControl /*out*/);   // ① why：SurfaceControl 以 out 参数跨 binder 回传，
                                        //    真正的 buffer 生产端在 app 侧，WMS 只分配 layer
    // … 省略：输入法/Insets 分支
}
```
> 进入本块时 app 持有的是旧 SurfaceControl；这次跨进程回来后 `mSurfaceControl` 可能指向新 layer。下一跳就看它怎么被包成 `Surface` 交给绘制线程——这也是闪屏排查要盯的赋值点（断点打在这一行，看新旧 nativeObject 是否不同）。

## 六、交付评分卡（每篇满分 20，<16 分重写，不许交付）

| 维度 | 分值 | 满分标准 |
|---|---|---|
| 锚点真实性 | 5 | 每个 `文件:行号`/类名 grep 核实，audit_anchors 通过数=总数 |
| 叙事流 | 4 | 单一流轴贯穿，块序=流序，分叉/回环显式画出 |
| 裁剪与注释 | 3 | 无整段搬运，省略分支有占位，注释全部在讲 why |
| 排障可操作性 | 3 | 每个实战问题都给验证过的命令/断点，且与本块有真实因果 |
| 思考题质量 | 2 | 闭环题需跨块推理才能答；无凑数题 |
| 独立可读 | 3 | 开篇一段话 + 0.0 名词表，不依赖前篇；HTML 结构校验/截图通过 |

评分要诚实：锚点真实性拿不到 5 分（有任何未核实锚点）的文章直接 0 容忍，先核实再谈别的。
