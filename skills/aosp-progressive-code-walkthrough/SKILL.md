# AOSP 渐进源码走读

用户学 AOSP 子系统时按「骨架 → 一小段代码 → 提问验证」推进，每轮只动一小块。

1. 先定位主题源码与笔记文件 `D:\openclaw\notes\<主题>\walkthrough-NN.md`（如 `notes\freeform\walkthrough-01.md`）；已存在就追加，不覆盖。
2. 动笔前先量方法跨度与分支数，再决定走多细：跨度用 `wsl -e bash -c 'awk "NR>=<起>{d+=gsub(/{/,\"{\")-gsub(/}/,\"}\"); if(NR><起 && d==0){print NR; exit}}" <文件>'`（外层用单引号，双引号转义会被 PowerShell 吃掉），分支数用 `sed -n '<起>,<止>p' <文件> | grep -c 'if ('`。跨度超过约 300 行就只讲判定点，把 insets/accessibility/transition 这类书记分支标成省略，并写明每个判定点的条件在哪个方法被赋值；骨架用调用/归属树加 `文件:行号` 锚点，并在同一条回复里附白话对照：记号说明（`→` 产出、`←` 被谁决定）、按顺序的八句话故事、五个名词、三个反直觉点。只给树不给白话，用户会回「骨架看不懂」。
3. 每轮只开 1–2 个约 30 行的代码窗口，按「输入在哪 / 产出什么 / 改了谁的状态」讲，不要整段贴文件。每个窗口开头标它跑几次（每帧 / 只一次，如 mFirst 首帧、首帧 attach 与焦点恢复），块序不表示重要性——每帧分支才是手感与掉帧的来源，一次性分支只在启动或首帧归因时展开。
   用户问「为什么这么强调某处」时先量化再答：`sed -n '<起>,<止>p' <文件> | grep -c '<标志>'` 取出现次数与条件数，`grep -n '<标志> = '` 找置位与清零点，用这些数字说清它影响首帧还是每帧。
4. 结尾提三个能自检的问题：入口在哪、哪个状态被谁改、改哪一行会改变行为。
5. 把代码窗口、关键行标注和白话对照追加进 walkthrough 文件，让下一轮从文件末段直接接上。
6. 回复用中文，行号写成 `文件:行号`；用户没要抽认卡就不做。

检查：同一回复里白话对照段落存在，且笔记末段能让下一轮不重读已讲过的部分。
