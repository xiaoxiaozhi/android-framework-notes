# 骨架阅读法（每轮随骨架一起给）

骨架是名词表，不是故事。为了让用户能读、能追问、能验，**每轮必须在三块之后追加本清单**（清单是配套读物，不算第四块；块数校验只看 ①②③）。

## 必给的五行

1. **一句话定位**：这条链解决什么问题，终点是什么形态（≤2 句）。
2. **三个接力边界**：分别标出「同线程直调」「跨进程（binder / socket）」「持锁区」，每条给行号。
3. **最小验证命令**：一条能在 1 分钟内跑完、能看到这条链痕迹的 `dumpsys` / `logcat` / `am` 命令。
4. **本链最贵的一行**：哪个方法/分支是绝大多数问题的落点，为什么。
5. **下一步追问的三个名字**：从骨架里挑 3 个方法名，各配一句「可以问它什么」。

## 规矩

- 五行加起来不超过 10 行正文，仍要能一屏读完。
- 行号必须与骨架同一基线；跨 12/13 时在边界行注明。
- 「最小验证命令」必须真能跑，不许写「观察一下」。
- 用户没要求解释时也要给——这是他读得懂骨架的前提，不是可选项。

## 反例

只给三块、不给阅读法，用户看到的是「方法名 + 行号」，会问「这什么意思」。**骨架缺阅读法等于交了一半。**
