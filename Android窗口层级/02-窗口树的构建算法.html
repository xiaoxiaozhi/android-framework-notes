一、全景：三个时间阶段

窗口层级树不是一次性建成的，而是在系统运行的不同时刻分阶段构建：

阶段时间点做什么源码位置
① 搭骨架 设备启动 / 显示器插入 创建 RootWindowContainer、DisplayContent，
由 DisplayAreaPolicyBuilder 构建全部 DisplayArea 层级		 DisplayAreaPolicyBuilder.build()
② 开门禁 应用进程连接 / 创建系统窗口 创建 WindowToken（或 ActivityRecord），
根据窗口类型挂入对应的 DisplayArea.Tokens		 DisplayContent.addWindowToken()
③ 挂叶子 addView() 调用 创建 WindowState，
挂入 WindowToken.mChildren，分配 Surface 层级		 WindowToken.addWindow()
✦ ✦ ✦ 关键区分 ✦ ✦ ✦
阶段① 只做一次（每个显示器），创建的是"架子"（DisplayArea）。
阶段② ③ 在系统运行中反复发生——每个新窗口都会触发。
本文重点讲解 阶段① 的算法（最复杂），附带二三阶段的完整流程。

三、三个关键角色速览：Feature / PendingArea / Window Layer

在深入算法之前，先搞清楚三个反复出现的角色：

角色是什么在这个阶段的作用
Feature 一个"区域需求"，如：
"我要把放大镜覆盖所有窗口类型"
"我要给挖孔屏排除状态栏"		 在构建时决定是否需要额外包一层 DisplayArea
PendingArea 一棵"中间临时树"
纯内存对象，不挂 Surface		 在 build() 中构建一棵逻辑树，
最后调用 instantiateChildren() 转化为真正的 DisplayArea
Window Layer 每种窗口类型对应一个数字

四、骨架怎么搭：DisplayAreaPolicyBuilder 构建算法

4.1 Feature 系统：按需分区

Feature 回答了 "在 DisplayArea 层级中是否需要为某个功能额外创建一层容器"这个问题。

每个 Feature 有一个 boolean[] mWindowLayers，长度 = 系统最大 layer 数 + 1。例如：

Feature 示例："OneHanded" 单手模式

            TYPE_NOTIFICATION_SHADE)
    .build();
// 生成的 mLayers 数组示例（部分）：
// layer=WALLPAPER(2)     → true   (被单手模式影响)
// layer=STATUS_BAR(15)   → false  (不被影响)
// layer=NAVIGATION(31)   → false  (不被影响)
// layer=TOAST(26)        → true   (被单手模式影响)

Feature 的顺序决定了 DisplayArea 的嵌套层级——先声明的 Feature 在上面。

4.2 PendingArea：内存中的中间树

在真正创建 DisplayArea 之前，算法先在内存中构建一棵 PendingArea 树——它是实际 DisplayArea 树的"蓝图"。

DisplayAreaPolicyBuilder.java — PendingArea
static class PendingArea {
    final int mMinLayer;                      // 覆盖的最小 window layer
    int mMaxLayer;                            // 覆盖的最大 window layer
    final ArrayList<PendingArea> mChildren = new ArrayList<>();  // 子节点
    final Feature mFeature;                    // 关联的 Feature（null = 普通 Tokens）
    final PendingArea mParent;                  // 父节点
    @Nullable DisplayArea mExisting;             // 复用已有的 DA（非 null 就不新建）
    boolean mSkipTokens;                       // 是否跳过 Tokens 创建
}
PendingArea 的三种"结果"：
mFeaturemExistingmSkipTokens最终创建的 DA 类型
非 nullnullfalse按 Feature.mNewDisplayAreaSupplier 创建（如 Dimmable）
nullnullfalsenew DisplayArea.Tokens("Leaf:min:max")
nullTaskDisplayAreatrue不复用！直接用传入的 TDA
nullImeContainertrue不复用！直接用传入的 IME 容器

4.3 三层遍历算法（HierarchyBuilder.build()）

这是整个构建流程的核心。算法分 三个嵌套循环：

1 Feature 遍历 → 为每个 Feature 在当前 layer 范围内创建必要的 DisplayArea 分支

2 Layer 遍历 → 为每个 window layer 分配叶子节点（DisplayArea.Tokens）

3 实例化 → 把 PendingArea 树转化为真实的 DisplayArea 对象并挂入树中

第一层遍历：为 Feature 建立分支

HierarchyBuilder.build() — Feature 遍历
// Feature 按声明顺序遍历（先声明的在上面）
for (int i = 0; i < mFeatures.size(); i++) {
    final Feature feature = mFeatures.get(i);
    PendingArea featureArea = null;

    for (int layer = 0; layer < maxWindowLayerCount; layer++) {
        if (feature.mWindowLayers[layer]) {
            // 这个 Feature 应用到当前 layer
            if (featureArea == null
                    || featureArea.mParent != areaForLayer[layer]) {
                // ★ 不能复用上一层的 area → 创建新的 PendingArea
                featureArea = new PendingArea(feature, layer, areaForLayer[layer]);
                areaForLayer[layer].mChildren.add(featureArea);
            }
            areaForLayer[layer] = featureArea;
        } else {
            // Feature 不应用到当前 layer → 断开引用
            featureArea = null;
        }
    }
}

这一步的核心逻辑：相邻的、同一 Feature 覆盖的 layer，共享一个 Feature DisplayArea。

第二层遍历：为每个 layer 创建叶子 Tokens

HierarchyBuilder.build() — 叶子层遍历
PendingArea leafArea = null;
int leafType = LEAF_TYPE_TOKENS;

for (int layer = 0; layer < maxWindowLayerCount; layer++) {
    int type = typeOfLayer(policy, layer);
    // typeOfLayer 返回三种值之一：
    //   APPLICATION_LAYER → LEAF_TYPE_TASK_CONTAINERS
    //   IME 的 layer → LEAF_TYPE_IME_CONTAINERS
    //   其他 → LEAF_TYPE_TOKENS

    if (leafArea == null
            || leafArea.mParent != areaForLayer[layer]
            || type != leafType) {
        // ★ 创建新的叶子节点 PendingArea
        leafArea = new PendingArea(null, layer, areaForLayer[layer]);
        areaForLayer[layer].mChildren.add(leafArea);
        leafType = type;

        if (leafType == LEAF_TYPE_TASK_CONTAINERS) {
            // 把 TaskDisplayArea 作为已有对象插入
            addTaskDisplayAreasToApplicationLayer(areaForLayer[layer]);
            leafArea.mSkipTokens = true;
        } else if (leafType == LEAF_TYPE_IME_CONTAINERS) {
            // 把 IME 容器作为已有对象插入
            leafArea.mExisting = mImeContainer;
            leafArea.mSkipTokens = true;
        }
    }
    leafArea.mMaxLayer = layer;  // 更新跨度范围
}

typeOfLayer 的判断逻辑

HierarchyBuilder.typeOfLayer()
private static int typeOfLayer(WindowManagerPolicy policy, int layer) {
    if (layer == APPLICATION_LAYER) {                // layer=2，应用层
        return LEAF_TYPE_TASK_CONTAINERS;             // → TaskDisplayArea
    } else if (layer == getLayer(TYPE_INPUT_METHOD)  // IME 的 layer
            || layer == getLayer(TYPE_INPUT_METHOD_DIALOG)) {
        return LEAF_TYPE_IME_CONTAINERS;              // → ImeContainer
    } else {
        return LEAF_TYPE_TOKENS;                      // → 普通 DisplayArea.Tokens
    }
}

三个 layer 类型的含义

Layer 类型叶子节点是什么为什么特殊处理？
TOKENS new DisplayArea.Tokens("Leaf:N:M") 普通系统窗口（壁纸、状态栏、Toast等），
直接创建 DisplayArea.Tokens 承载
TASK_CONTAINERS 复用已创建的 TaskDisplayArea 应用窗口不走 Tokens，而是进入 TaskDisplayArea → Task → ActivityRecord 的层次结构
IME_CONTAINERS 复用已创建的 ImeContainer IME 需要特殊动画和焦点处理，单独挂在一个 RootDisplayArea 下

示例：PeningArea 树造出来的样子

假设系统定义了 WindowedMagnification 和 OneHanded 两个 Feature，生成的 PendingArea 树如下：

PendingArea (root, 虚拟根)
 ├── PendingArea [Feature:WindowedMagnification, layer:0..26]
 │    ├── PendingArea [Feature:OneHanded, layer:0..14]
 │    │    ├── PendingArea [Tokens, layer:0..1]
 │    │    └── PendingArea [Tokens, layer:2..14]
 │    └── PendingArea [Feature:OneHanded, layer:15..26]
 │         ├── PendingArea [Tokens, layer:15..19]
 │         ├── PendingArea [TaskDisplayArea ★, layer:APP]     ← TaskDisplayArea 直接插入
 │         └── PendingArea [Tokens, layer:21..26]
 └── PendingArea [Tokens, layer:27..31]                       ← 放大镜外的层
✦ ✦ ✦ 关键洞察 ✦ ✦ ✦
相邻的 layer、同一个 Feature 覆盖、且同一叶子类型的 → 共享一个 DisplayArea.Tokens。
这就是为什么 所有应用窗口都进入同一个 TaskDisplayArea——因为它们都在 APPLICATION_LAYER。
这也是为什么 壁纸和启动画面各在一个 DA.Tokens——它们的 layer 虽然相邻，但 Feature 覆盖范围不同。

4.4 instantiateChildren：从蓝图到实物

PendingArea 树建好后，instantiateChildren() 递归遍历它，把每个 PendingArea 转换为真正的 DisplayArea 对象，并挂入树：

PendingArea.instantiateChildren()
void instantiateChildren(DisplayArea<DisplayArea> parent,
        DisplayArea.Tokens[] areaForLayer, int level,
        Map<Feature, List<...>> areas) {

    // ★ 先按 mMinLayer 排序子节点（保证 Z-order 正确）
    mChildren.sort(Comparator.comparingInt(a -> a.mMinLayer));

    for (PendingArea child : mChildren) {
        // ① 创建真正的 DisplayArea 对象
        DisplayArea area = child.createArea(parent, areaForLayer);
        if (area == null) continue;     // TaskDisplayArea 不新建

        // ② ★ 挂入父节点
        parent.addChild(area, POSITION_TOP);

        // ③ 记录 Feature → DisplayArea 映射
        if (child.mFeature != null) {
            areas.get(child.mFeature).add(area);
        }

        // ④ 递归处理子节点
        child.instantiateChildren(area, areaForLayer, level + 1, areas);
    }
}

createArea() — 决定创建什么类型的 DA

PendingArea.createArea()
private DisplayArea createArea(DisplayArea<DisplayArea> parent,
        DisplayArea.Tokens[] areaForLayer) {

    if (mExisting != null) {                        // IME 容器、TaskDisplayArea
        if (mExisting.asTokens() != null) {
            fillAreaForLayers(mExisting.asTokens(), areaForLayer);
        }
        return mExisting;                           // 直接用已有对象
    }
    if (mSkipTokens) return null;                     // 跳过（TDA / IME）

    // 确定 DisplayArea 类型
    DisplayArea.Type type;
    if (mMinLayer > APPLICATION_LAYER) type = ABOVE_TASKS;
    else if (mMaxLayer < APPLICATION_LAYER) type = BELOW_TASKS;
    else type = ANY;

    if (mFeature == null) {
        // ★ 创建 DisplayArea.Tokens
        DisplayArea.Tokens leaf = new DisplayArea.Tokens(
            parent.mWmService, type,
            "Leaf:" + mMinLayer + ":" + mMaxLayer);
        fillAreaForLayers(leaf, areaForLayer);   // 填充 layer 映射表
        return leaf;
    } else {
        // ★ 按 Feature 指定的工厂创建（如 Dimmable DA）
        return mFeature.mNewDisplayAreaSupplier.create(
            parent.mWmService, type,
            mFeature.mName + ":" + mMinLayer + ":" + mMaxLayer,
            mFeature.mId);
    }
}

fillAreaForLayers() — 注册到 layer 查找表

fillAreaForLayers()
private void fillAreaForLayers(DisplayArea.Tokens leaf,
        DisplayArea.Tokens[] areaForLayer) {
    for (int i = mMinLayer; i <= mMaxLayer; i++) {
        areaForLayer[i] = leaf;   // 按 layer 索引 → 指向对应的 DisplayArea.Tokens
    }
}

这个查找表 (areaForLayer) 之后在 onHierarchyBuilt() 中赋值给 RootDisplayArea.mAreaForLayer，用于 findAreaForWindowType() 的 O(1) 查找：

按窗口类型查找 DisplayArea：O(1)
// 窗口来了 → 根据类型算出 layer → 查表 → 直接得到应该挂载的 DisplayArea.Tokens
int windowLayerFromType = mWmService.mPolicy
    .getWindowLayerFromTypeLw(windowType, ownerCanManageAppTokens);
return mAreaForLayer[windowLayerFromType];   // O(1) 查表！

4.5 onHierarchyBuilt() — 收尾

递归创建完成后，调用 onHierarchyBuilt() 把最终状态缓存在 RootDisplayArea 中：

RootDisplayArea.onHierarchyBuilt()
void onHierarchyBuilt(ArrayList<Feature> features,
        DisplayArea.Tokens[] areaForLayer,
        Map<Feature, List<DisplayArea<...>>> featureToDisplayAreas) {

    if (mHasBuiltHierarchy) throw new IllegalStateException(...);  // 只执行一次

    mHasBuiltHierarchy = true;
    mFeatures = Collections.unmodifiableList(features);
    mAreaForLayer = areaForLayer;              // ★ 缓存 layer 查找表
    mFeatureToDisplayAreas = featureToDisplayAreas;  // ★ 缓存 Feature→DA 映射
}

此时一棵完整的 DisplayArea 树就已经在内存中了。树中的每个 DisplayArea.Tokens 节点都在等待 WindowToken 的到来。

五、门禁与叶子：Token 与 WindowState 怎样挂树

5.1 客户端侧：这个窗口的 WindowManager 从哪来

5.2–5.4 讲的都是 WMS.addWindow() 之后的事。但请求到达 WMS 之前，窗口是先由客户端的 WindowManagerImpl 加进去的；而用哪个 WindowManagerImpl 实例，由三个工厂方法决定。三者只是同一个私有构造器的三套参数预设，差别就在 (Context, parentWindow, windowContextToken) 这个三元组：

WindowManagerImpl.java — 三个工厂方法（@hide 类，:72/:74，第三方 App 调不到）

        @Nullable IBinder windowContextToken) { ... }

// :106 ★工厂① 只换 parentWindow，Context 与 windowContextToken 原样继承（实例方法）
public WindowManagerImpl createLocalWindowManager(Window parentWindow) {

5.2 非应用窗口：WindowToken 创建即挂树

当 WMS.addWindow() 发现没有现成的 token 时，新建一个 WindowToken。对于非应用窗口（系统窗口），token 建好就立即通过 DisplayContent.addWindowToken() 挂入树：

DisplayContent.addWindowToken()
void addWindowToken(IBinder binder, WindowToken token) {
    mTokenMap.put(binder, token);              // 记录映射
    token.mDisplayContent = this;

    if (token.asActivityRecord() == null) {     // ★ 非应用 token
        DisplayArea.Tokens da = findAreaForToken(token).asTokens();
        da.addChild(token);                        // ★ 挂入 DisplayArea.Tokens
    }
}

5.3 应用窗口：ActivityRecord 通过 Task 挂树

应用窗口的 token 是 ActivityRecord（extends WindowToken）。它不经过 DisplayContent.addWindowToken()，而是由 ActivityStarter 创建 ActivityRecord 后，调用 Task.addChild(ActivityRecord, POSITION_TOP) 挂入树：

Task.addChild()
// ActivityRecord 作为子节点挂入 Task
void addChild(WindowContainer child, int index) {
    index = getAdjustedChildPosition(child, index);
    super.addChild(child, index);  // → WindowContainer.addChild → 插入 mChildren

    // 更新 Task 元数据
    final ActivityRecord r = child.asActivityRecord();
    if (r == null) return;
    r.inHistory = true;
    if (!hadChild) {
        setActivityType(r.getActivityType());  // 首个 Activity 决定 Task 的类型
    }
}

5.4 最末一步：WindowState 挂到 Token 下

无论应用窗口还是系统窗口，最终的 WindowState 都通过 WindowToken.addWindow() 挂入：

WindowToken.addWindow() — 最终插入
void addWindow(final WindowState win) {
    if (win.isChildWindow()) return;        // 子窗口挂到父 WindowState

    if (!mChildren.contains(win)) {
        addChild(win, mWindowComparator);   // ★ 按 baseLayer 排序插入
        mWmService.mWindowsChanged = true;
        win.getParent().assignChildLayers();  // ★ 递归分配 Surface 层级
    }
}
✦ ✦ ✦ 三个阶段的树状态 ✦ ✦ ✦
阶段① 后：树 = DisplayArea 层 + TaskDisplayArea（空 Task）
阶段② 后：树 = 阶段① + WindowToken / ActivityRecord（挂入 Task 或 DA.Tokens）
阶段③ 后：树 = 阶段② + WindowState（完整）

从系统启动到窗口挂树的完整 DAG

━━ 系统启动 ━━
SystemServer → WMS.main() → new WMS() {
    mRoot = new RootWindowContainer()
    mDisplayAreaPolicyProvider = DisplayAreaPolicy.Provider.fromResources()
}

━━ 显示器注册 ━━
RootWindowContainer.createDisplay()
  → new DisplayContent() {
        mDisplayAreaPolicy = mDisplayAreaPolicyProvider
            .instantiate(...)                            // ① DefaultProvider
              → new TaskDisplayArea()                     // ② 创建 TaskDisplayArea
              → new DisplayAreaPolicyBuilder()            // ③ Builder
                  .setRootHierarchy(rootHierarchy
                      .setImeContainer(imeContainer)
                      .setTaskDisplayAreas(tdaList)
                      .addFeature(...))
                  .build(wmService)                      // ④ 入口
                    → validate()
                    → rootHierarchy.build()               // ⑤ 构建 PendingArea 树
                    → root.instantiateChildren(...)       // ⑥ 转化为真实 DA
                    → mRoot.onHierarchyBuilt(...)          // ⑦ 缓存 layer 查找表
                    → return new Result(...)
    }

━━ 窗口添加 ━━
WMS.addWindow()
  → getDisplayContentOrCreate()                      // 确保有 DisplayContent
  → 查找/创建 WindowToken
      → new WindowToken.Builder(...).build()          // 新建 token
      → displayContent.addWindowToken(token)           // ★ 系统窗口 token 挂树
          → findAreaForToken()                       // O(1) 查 mAreaForLayer
          → da.addChild(token)                        // 挂入 DisplayArea.Tokens
  → 或 ActivityRecord new ActivityRecord(...)
      → task.addChild(activityRecord)                // ★ 应用窗口 token 挂树
  → new WindowState(...)                             // 创建窗口
  → win.mToken.addWindow(win)                          // ★ WindowState 挂树
      → addChild(win, mWindowComparator)             // 按 baseLayer 插入 mChildren
  → win.getParent().assignChildLayers()               // 递归分配 Surface Z-order
