切壁纸闪黑：该盯哪些日志

方向Tag / 关键字看什么
壁纸设置WallpaperManagerService：setWallpaper which=、Crop done、bindWallpaperComponentLocked设置 → 裁剪 → 重绑的耗时与顺序；这段是否和转场重叠
壁纸渲染ImageWallpaper：onSurfaceCreated、onSurfaceChanged、drawFrameSurface 是否在转场中被重建；重建就会有一帧没有内容
WMSWindowManager（含 WallpaperController）：New wallpaper target、updateWallpaperVisibility壁纸窗口的可见性、目标窗口、偏移是否在切换瞬间抖动
转场Transitions / Shell：Start transition、finishTransition黑闪是否落在 Start→Finish 之间；这是最重要的时间窗口
合成SurfaceFlinger / BufferQueue / BLASTBufferQueue：createLayer、destroyLayer、dequeueBuffer、queueBuffer壁纸层是否被销毁重建；是否出现空 buffer / 没有可用帧
稳定性AndroidRuntime、ANR in com.android.systemui、WatchdogSystemUI 崩溃/重启会连带 ImageWallpaper 重画，表现就是闪黑

判据：转场窗口内，壁纸窗口 mDrawState != HAS_DRAWN 或 mHasSurface=false，且日志里能看到 Surface 重建 / 壁纸重绑 —— 三者同时出现，基本可以锁定。

抓取命令

adb logcat -c
adb logcat -v threadtime -s WallpaperManagerService ImageWallpaper WindowManager SurfaceFlinger BufferQueueProducer BufferQueueConsumer Transitions ActivityTaskManager AndroidRuntime > wallpaper_switch.log

# 触发一次切壁纸（设置/相册/Launcher 长按），闪黑后立刻：
adb shell dumpsys window windows > window.txt
adb shell dumpsys SurfaceFlinger --list | grep -i wallpaper > sf_layers.txt
adb shell dumpsys activity service com.android.systemui/.SystemUIService > sysui_dump.txt

更精确的方式：用 Winscope / Perfetto 抓一次 transition + window trace，和 logcat 时间轴对齐；本工具可以先做粗定位。

解析基于 AOSP 12 的 dumpsys 字段；不同版本/OEM 可能字段略有差异，缺失字段会标记为“未知”。
