目标锁定 B。下面保留三赛道对照，是为了说清「为什么不是 A/C」；从第二章起，全部内容按 B 裁剪。

B 的三个「能」（验收标准，达不到就不算入门）

1能改——改一处系统行为（状态栏 / 导航栏 / 默认策略），编译刷机看到效果。

2能查——给你一个 ANR 或系统 bug，能独立定位到根因（不是猜）。

3能讲——三大服务全链路时序图讲得出来，每步带类名 + 文件 + 行号。

B 的三个「不」

⚠️ 别踩 ① 不做 API 调用工程师——那是 A；会调 API 不等于懂系统。② 不背结论——所有说法都要能追到源码行号。③ 不跳过 Binder——它是 B 赛道的第一道分水岭，跳过的人永远在表层打转。

🧠 先想一下 三个月后你希望自己能回答哪个问题：「我改过 SystemUI 的某个行为并刷机验证了」，还是「我看完了 AMS 源码」？B 岗看的是前者——能改 + 能查才是 B 的货币。

一、实际开发中哪一部分岗位最多

下面排序来自 2026-10 当天抓取的招聘样本（联想 Framework 工程师 / Framework 多媒体 / 性能优化岗、光庭信息车载 Android FW/HAL、智联上海与 Indeed 的 Framework 岗列表）。属于样本观察，不是全量统计，方向性结论可靠，具体数量别当精确数字用。

1️⃣ 车载 / 智能座舱 FW + HAL —— 当前最大的增量池

光庭信息「Android FW/HAL」JD 原文：「负责智能座舱 Android 系统 Framework 层、HAL 层核心模块的定制开发、功能迭代、软硬件联调与量产维护」「依托 Binder、HIDL/AIDL 通信机制，打通系统层、硬件驱动层交互链路」；智联上海样本里「车载项目 + Framework」「车载项目 Java/C++」反复出现。

要求具体到哪一步
AOSP 编译/裁剪/定制能按整车需求裁服务、改默认配置、出 ROM
Framework 系统层 或 HAL（HIDL/AIDL）二选一精通，另一项能对接
至少擅长车载任一模块车控 CarService/VehicleHAL、车载音频、相机、网络、车载诊断、系统策略定制
量产问题闭环稳定性异常、功能适配失效、服务崩溃、性能功耗
结论 这是目前最容易进、也最缺人的方向。代价是项目节奏紧、偏交付；收获是能快速积累「完整周期」经验。

2️⃣ 系统稳定性 / 性能优化 —— 每家大厂都常备，永远缺

联想「Android 性能优化工程师」要求原文：「深入理解 Android 系统架构，熟悉 AMS、WMS、Binder」；联想「Android framework Engineer」职责第 2 条直接就是「ANR、Crash、内存泄漏、卡顿、冻屏 等疑难问题」。

结论 这是最能体现「资深」的方向，也是 Framework 岗面试的核心考察区。它不看你背了多少，只看你能不能定位。

3️⃣ Framework 多媒体（音视频 / 图形）

联想「Framework 多媒体工程师」：「深入理解 AudioFlinger / AudioPolicyManager 等核心流程，熟悉主流音视频编码协议和编解码流程」，且要求熟悉图形模块。

4️⃣ 短距通信 FW（WiFi / BT / GPS / NFC）

联想「Framework 短距通信工程师」独立成岗，说明这是有稳定池子的细分方向。

5️⃣ 手机厂商框架定制（SystemUI / 多窗口 / 折叠屏 / 动效）

需要 WindowManager / SystemUI / 多屏多窗。你正在学的 WMS 正好落在这里。

6️⃣ 系统应用 / ROM 定制（Settings、Launcher、OTA、权限中心）

一句话 想快进圈 → 车载 FW/HAL；想走深 → 稳定性 + 性能优化；想炫技 → 图形 / 多媒体。 三者都以 Binder + AMS + WMS + SystemServer 为公共地基，所以地基不会白学——这也是为什么你的 WMS 功夫在任何一条线上都算数。

二、哪些最重要：必备清单 vs 加分项

🔴 必备（面试必问、日常必用、不学就干不了活）

#知识点一句话为什么源码位置（AOSP 12）
1AOSP 编译与刷机不会编译刷机 = 不会调试系统build/、device/、lunch/m
2Binder所有跨进程的根，AMS/WMS/PMS 全靠它frameworks/native/libs/binder/、core/java/android/os/Binder.java
3Handler / Looper / MessageQueue所有异步与主线程的根，ANR 的源头core/java/android/os/Looper.java
4init → Zygote → SystemServer一切系统服务诞生的地方system/core/init/、ZygoteInit.java、SystemServer.java
5AMS（ActivityTaskManagerService）四大组件 + 任务栈 + 生命周期wm/ActivityTaskManagerService.java
6WMS窗口、层级、显示、输入的前提wm/WindowManagerService.java
7PMS（PackageManagerService）安装、权限、包解析pm/PackageManagerService.java
8SurfaceFlinger + 图形栈像素怎么上屏，卡顿/掉帧必查native/services/surfaceflinger/
9Input 分发触摸/按键到窗口的全链路native/services/inputflinger/
10调试工具链logcat / dumpsys / Systrace / Perfetto / bugreport / gdb—
11SELinux 与权限模型改系统必碰的拦路虎system/sepolicy/
🍔 读法：1–4 是「地基」，5–7 是「三大器官」，8–9 是「让人看得见摸得着」，10–11 是「干活的手艺」。地基不牢，后面全是背题。

🟡 加分（决定你值多少钱、能不能拿高薪）

加分项对应岗位学到什么程度
HAL 层（HIDL / AIDL）车载、ODM能自己写一个 HAL 接口并完成 framework→HAL→驱动联调
C++ / Native / JNI全部（因为 frameworks/native、frameworks/av 全是 C++）能静读 native 层代码
稳定性专精大厂稳定性团队能从 bugreport 独立定位 ANR / native crash 根因
性能专精性能优化岗Perfetto 抓帧能指出耗时构成，能做开机/内存优化
车机特有座舱团队CarService / VehicleHAL / CAN 总线 / 多屏互动
图形进阶厂商渲染团队RenderEngine / HWC / BLAST / Choreographer
AI 端侧2026 年不少 JD 已列入加分TFLite / MNN / NCNN 任一，懂量化/剪枝
🐛 常见误区 很多人把「会用 dumpsys 看几眼」当成学完了 AMS/WMS。岗位要求的是能拿它定位问题——顺序永远是「现象 → 假设 → 用工具验证 → 落到具体类/方法/行号」，而不是「我知道这个服务大概干什么」。

三、学习路线图：六阶段

总原则 问题驱动 + 必须动手。每阶段都要「改一处代码 → 编译 → 刷机 → 观察现象」的闭环。光看不练的 framework 学习等于白学，因为所有知识都长在运行时行为上。

阶段 0：地基（1–2 周）

内容到什么程度
Linux 基础进程/线程/内存/文件系统/信号；ps top strace readelf
Java 进阶反射、注解、并发、AIDL 语法
C++ 基础指针、引用、类、STL——够读 frameworks/native
构建系统Make / Soong / Blueprint、Ninja 概念
Git + repoAOSP 是多仓，repo 必须会

验收：能写 shell/python 脚本自动化；能看懂 Android.bp。

阶段 1：AOSP 上手与调试体系（2–3 周）

1拉源码——你本机已有 /home/book/aosp12。

2会编译——lunch / m / mmm / adb sync / 单模块编译。

3会刷机——fastboot flashall，或 adb push 单文件替换（调试期更常用）。

4调试四件套——dumpsys（activity/window/input/package/SurfaceFlinger）、cmd window、Perfetto/Systrace、bugreportz。

验收：独立把 SystemUI 的一个字符串/颜色改掉，编译、刷机、看到效果。这一步做到，后面所有阶段才有反馈回路。

阶段 2：进程与 IPC —— 系统的骨架（3–4 周）★ 最容易被跳过、但最关键

#学什么关键点
1init 与 init.rc系统第一个进程；on boot / service / class_start
2Zygote所有 Java 进程的母体；fork + COW；预加载了什么
3SystemServer系统服务的诞生地：startBootstrapServices / startCoreServices / startOtherServices
4Binder（重点中的重点）Java 侧 Binder/BinderProxy/AIDL/ServiceManager；Native 侧 IPCThreadState/ProcessState/binder.c
5Handler / Looper / MessageQueueIdleHandler、同步屏障（Barrier）与 VSYNC 的关系（后面图形栈会用到）
6AIDL / HIDL 写法能独立定义接口并实现服务端
🧠 自测题（够格才算过） 一次跨进程调用，数据从 Java 层出发到驱动再回到对端，一共拷贝几次？各在哪一层？——答不上来就说明 Binder 还没学透。

验收：自己写一个 AIDL 服务，从另一个进程调用成功；能用 dumpsys 看到服务注册表。

阶段 3：三大主服务 —— 系统的器官（4–6 周）

服务学什么你的进度
WMS窗口树、DisplayArea、层级/Z 序、遍历刷新、Surface 创建、事务提交✅ 已深入（00–06 篇）
AMSstartActivity 全链路、ActivityRecord/Task、生命周期、launchMode、进程管理、回退栈⬜ 下一个重点
PMSAPK 解析、签名校验、权限、安装流程、包扫描⬜ 之后
学习顺序 WMS → AMS → PMS。你已把 WMS 走通，而 WMS 的上游正是 AMS（ActivityRecord extends WindowToken——你 06 篇已经摸到了），顺着这条线接 AMS 是最省力的路径。

验收：能画出「startActivity → ActivityRecord 挂进 Task → 首帧上屏 → 删除」的完整时序图，每步带类名 + 行号。

阶段 4：图形与输入 —— 让人「看得见、摸得着」（3–4 周）

三条纪律（比路线图本身更重要）

1不要只读书/只读源码——每学一块，必须有一次「改 → 编 → 刷 → 看」的闭环。

2一切结论落到「类名 + 文件 + 行号」——含糊的「大概在 AMS 里」不算学会。

3建自己的问题库——遇到的每个 ANR/Crash/黑屏都写下来（现象 → 因果 → 怎么查），这就是你未来的面试题库和工作手册。

六、你的起点与下一步

你已经把阶段 3 的 WMS 部分走得非常深（窗口层级 00–06 篇、AOSP12 源码树、ASfP、WSL 环境全齐）——很多人半年都到不了这个位置。所以你的路线不需要从头走。

已完成：阶段 1（环境/编译 ✅ 部分）＋ 阶段 3 的 WMS ✅ │ ├─① 补 Binder （阶段 2 的核心；你一直在用它但没系统学过） │ ├─② 接 AMS （阶段 3 续；顺着 ActivityRecord = WindowToken 走最顺） │ ├─③ 补 PMS （阶段 3 收尾） │ ├─④ 图形/输入回炉 （阶段 4；你 03/04/05 篇已覆盖大半，补 RenderThread 与 Perfetto） │ ├─⑤ 稳定性与性能 （阶段 5；最该花时间，直接对应岗位最多的方向之一） │ └─⑥ 按目标岗选专项 （车机 HAL / 手机厂商定制 / 多媒体）

下一步最该做的三件事

1补 Binder——它是你已学的 WMS 全链路的底层（addToDisplayAsUser 就是一次 Binder 调用）。你现在的知识在 Binder 处有个「断口」。

2接 AMS——把 06 篇结尾的悬念（ActivityRecord 从哪来、到哪去）接着写下去，这正好是路线图里的 07 篇。

3建「实战坑」档案——你文章里已经在写「🐛 实战」和思考题了，把这个习惯扩展成一份独立的《Android 系统问题库》（现象/因果/排查命令），面试和干活都靠它。

七、B 岗面试必答清单（B 赛道专用）

这 10 题是 B 岗技术面的主战场。每题都要求答案能落到类名 / 行号，含糊过关会被追问到底。

#问题考什么参考锚点（AOSP 12）
1一次 startActivity 从 App 到新 Activity 首帧的完整链路跨 ATMS → WMS → App 的全局观ATMS.startActivity → ActivityStarter.execute → ActivityRecord → ViewRootImpl.setView
2Binder 一次调用数据拷贝几次？为什么？oneway / 死亡通知IPC 底层libs/binder/、IPCThreadState、Binder.java
3Handler 的同步屏障（Barrier）是什么？和 VSYNC 什么关系异步与渲染MessageQueue.postSyncBarrier、Choreographer
